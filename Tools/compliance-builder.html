Custom compliance builder

Draft: This tool is new and has not been tested in class yet.

Pick the checks a Windows device must pass. The page builds the two files a custom compliance policy needs: the PowerShell discovery script and the JSON rules file. The page signs in nowhere and sends nothing: everything stays in your browser.

1. Policy
2. Checks

Every check becomes one value in the script output and one rule in the JSON. A check that fails to read its value returns a fallback value instead (shown in each check). Choose rules that fail with the fallback, so a broken check never makes a device compliant – with NotEquals on text, the fallback NotFound passes. In the remediation title, {ActualValue} shows the value the script discovered.

3. Result

    4. Use the files
    1. Test on a client first, in an elevated Windows PowerShell (64-bit): PowerShell.exe -ExecutionPolicy Bypass -File .\Test-CustomCompliance.ps1 -ScriptPath .\<script>.ps1 -RulesPath .\<rules>.json (from Compliance in the Labfiles).
    2. Intune admin center → Endpoint security → Device compliance → Scripts → Add → Windows 10 and later: paste the script. Leave Run this script using the logged on credentials at No (System context) and set Run script in 64 bit PowerShell Host to Yes – the 32-bit default reads the redirected registry (WOW6432Node) and the 32-bit view of System32.
    3. Devices → Compliance → Create policy → Windows 10 and later → Custom Compliance: Require, select the script, upload the JSON. Intune validates the JSON and shows the rules as a table.

    Limits: one discovery script per policy and one policy per script, script output up to 1 MB, run time up to 10 minutes on Windows, JSON up to 100 KB and 100 rules. Creating discovery scripts needs the Default scope tag.
