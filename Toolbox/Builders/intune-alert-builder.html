Intune alert builder

Pick the Intune events that support and security should hear about. The page builds the KQL queries for the IntuneAuditLogs table and one ARM template with an action group (email) and one log search alert rule per event. You deploy the template in your Azure subscription. The page signs in nowhere and sends nothing: everything stays in your browser.

Needs: an Azure subscription with a Log Analytics workspace, and Intune Diagnostic settings that send AuditLogs to that workspace (step 1). Log Analytics and alert rules cost money per GB and per rule.

1. Send the Intune audit log to Log Analytics
  1. Intune admin center → Reports → Diagnostic settings → Add diagnostic setting.
  2. Name Intune to Log Analytics, select AuditLogs (optional: OperationalLogs), select Send to Log Analytics workspace and pick the workspace → Save.
  3. Change something in Intune, wait up to 30 minutes, then run the check query in the workspace (Logs). It shows the exact OperationName values your tenant writes – the alerts below filter on them.

      Each alert query keeps only entries that reached the workspace since the last check (ingestion_time()), so one event sends one mail even though the look-back window overlaps. Test: trigger one event (for example run a remediation on demand on a lab device), wait for the next evaluation plus ingestion delay, check the mail. Azure portal → Monitor → Alerts lists every fired alert. Sources: Send Intune log data to Azure Monitor, IntuneAuditLogs table, Resource Manager templates for log search alerts.

      6. Optional: connector and token check

      Expiring or broken connectors are not in the audit log. This second template adds a daily check: an Automation account runs the runbook Send-IntuneConnectorStatus.ps1 with its managed identity, reads the Apple MDM push certificate, VPP and ADE tokens, Managed Google Play and Mobile Threat Defense from Graph and writes one row per connector to the table IntuneConnectorStatus_CL. An alert rule mails every daily check that finds a connector in Warning (expires within 7 days, last sync more than 1 day ago) or Unhealthy (expired, last sync 3 or more days ago) – the thresholds of Tenant administration → Connector status.

      Uses the workspace, region, email and name prefix from step 2. Deploy it once, separately from the alert template: you can redeploy the alert template as often as you like without touching the Automation account. The template creates a custom table, a data collection rule, an Automation account with runbook and daily schedule, a role assignment (Monitoring Metrics Publisher on the data collection rule), the action group and one alert rule. ARM cannot grant Graph permissions – step 2 of the PowerShell block does that. Status draft: not yet deployed.

      The runbook job output (Automation account → Jobs → a job → Output) shows the same table. Sources: Logs Ingestion API in Azure Monitor, Using a system-assigned managed identity for an Azure Automation account, scheduledQueryRules template reference.
