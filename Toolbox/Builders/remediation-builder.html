Remediation builder

Draft: This tool is new and has not been tested in class yet.

Pick what a Windows device must look like. The page builds the two scripts of an Intune remediation script package: the detection script finds the issue and ends with exit 1, the remediation script fixes it. It also tells you which package settings to choose. The page signs in nowhere and sends nothing: everything stays in your browser.

1. Package
2. Checks

The detection script runs every check and lists all issues on one output line. The remediation script checks each item again and fixes only what is wrong. A check without a fix only reports – the package still shows the issue in the report.

3. Scripts

      Downloads are UTF-8 without BOM, as Intune needs with the signature check on.

      4. Package settings
      1. Test on a client first, in an elevated Windows PowerShell (64-bit): run the detection script and check $LASTEXITCODE (1 = issue), run the remediation script, run the detection script again (0). For scripts that run as the user, test in a normal PowerShell window.
      2. Intune admin center → Devices → Scripts and remediations → Remediations → Create: upload both files (uploading keeps the encoding right), choose the settings from the table, assign a device group and a schedule.
      3. Test one device right away: Devices → device → Run remediation. Results: Remediations → package → Device status, with the pre- and post-detection output.

      Rules from Microsoft Learn: detection exit 1 = issue found, so the remediation runs; any other exit code or empty output = no issue. Output up to 2,048 characters. No restart commands, passwords or personal data in the scripts. Needs Windows Enterprise E3/E5 (or A3/A5, or VDA) for the users. Up to 200 script packages. Source: Remediations.
